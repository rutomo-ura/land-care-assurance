# LandCare Assurance v1.0.0 release notes

**Release date:** 2026-07-14
**Release channel:** GitHub Pages from `master`

## Summary

LandCare Assurance v1.0.0 establishes the operational baseline for a map-first assurance workflow: live ArcGIS-aware monitoring, executive KPI reporting, source-aware metric definitions, daily refresh controls, and a reusable executive BI design system.

## Highlights

- Delivered an executive KPI Dashboard with a completion trend, contractor queue, finance, parcel, submission, and expense views.
- Refined Map Monitor into an operational workspace with clearer context, integrated metric tiles, and decision-focused panels.
- Added **Executive Map Brief** export. Users start with strategic default metrics and can choose additional metrics before preparing the PDF.
- Documented source-of-truth rules so current inventory, monthly assignments, survey evidence, and finance are not incorrectly blended.
- Documented the daily VM refresh, Task Scheduler operations, logs, validation gates, and failure triage.
- Added a portable Executive BI Design System for future dashboard projects.

## Data and metric guardrails

- Active completion = matched returned evidence / Active assigned parcels.
- Request Only remains portfolio context and is not in the Active completion denominator.
- Raw all-period survey coverage is not equivalent to assignment-matched returned evidence.
- Finance context comes from the budgeting workbook published through `finance_summary.json`.

## Operational checks included

- GitHub Pages workflow validates required site/data files and data-count relationships.
- Daily validation checks generated dates, JSON integrity, feature counts, duplicate parcel-month records, status counts, finance totals, and selected regression conditions.
- VM runbook provides log paths, status JSON, scheduler proof steps, and failure triage.

## Known release checks

- Complete a manual browser print-preview check of the Executive Map Brief before a live presentation.
- On the target VM, prove one successful manual refresh and one scheduled refresh with `LastTaskResult = 0` and same-day success status JSON.
